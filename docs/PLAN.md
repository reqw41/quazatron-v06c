# План переноса Quazatron на Вектор-06Ц (полный, 24.10.2026)

Источник — оригинал ZX 48K (Hewson 1986), размечен полностью: `build/quaz.asm` собирается обратно байт в байт,
имена — `docs/symbols.txt`, карта — `docs/MAP.md`, оглавление кода — `docs/FUNCS.md`, аудит — `docs/AUDIT.md`,
покрытие трассами 99 %. Версия автора Турбо+ (`ref/turbo/`) — только ориентир по цвету, не публикуется.

Порядок, утверждённый владельцем:
1. **Порт под Вектор с Z80**: код ZX исполняется как есть, работа — склейка с железом и память.
2. **Перевод на i8080** (ванильный Вектор), демо прокрутки в `demo/` — задел.
3. **Цвет, звук, выпуск.**
Аппаратную прокрутку Вектора не использовать.

## Этап 1. Порт на Z80: раскладка памяти и запуск

### 1.1. Раскладка (уточняет PORT_Z80.md)
Экран Вектора — 4 плоскости 8000–FFFF; игра занимает 61A9–EE90, то есть все четыре. Видимой делаем одну
плоскость **8000–9FFF**, палитра смотрит только на её бит (плоскости 1–3 — данные игры, на экран не влияют).

| адреса | что |
|---|---|
| 0000–00FF | старт Вектора; **0x0038 — вход кадрового прерывания** (`jp vec_isr` → опрос клавиатуры → `isr` игры) |
| 0100–0FFF, 1530–1FFF | склейка Вектора: перевод экрана, клавиатура, джойстик, звук, таблицы |
| 1000–152F | копия начала ПЗУ ZX 48K, перенесённая с нуля (`rnd` читает 0000–03FF). В сборке i8080 не нужна: `rnd` — байты своего кода C000–C3FF, CIRCUIT (26.10.2026) — графика палуб 3700–382B (ZX 9700; стенд кладёт её на место ПЗУ 0400–052B), 1000–152F — под код |
| 2000–3FFF | **окно 8000–9FFF игры, перенесённое со смещением −0x6000** (t_field, t_deckgfx, кэш плиток; таблица IM 2 больше не нужна) |
| 4000–5AFF | **теневой экран ZX**: игра пишет в него как в экран ZX — битмап и атрибуты, ничего не портит |
| 5B00–61A8 | свободно; стек ниже 61A5 (игре нужно ≈ 20 байт, минимум 6192) |
| 61A9–7FFF, A000–EE90 | игра на своих адресах (A000–EE90 — в невидимых плоскостях) |
| 8000–9FFF | видимая плоскость |

Почему окно уходит в 2000, а не в 4000 (как в первой редакции PORT_Z80): игра пишет в атрибуты ZX напрямую
из 27 мест (панель, лифт, меню, захват, монитор). С теневым экраном в 4000–5AFF их не надо трогать.

### 1.2. Перенос окна 8000–9FFF → 2000–3FFF
Правки в `build/quaz.asm` как замены (скрипт `tools/port_patch.py`, сборка повторяемая):
- 21 константа: BE38 (9603), BE42 (8080), C05A/C07D/C0A0, C1B7, C241, D971/DF6C/E3DA (8078), DE83/DE8B (9C00/9C01),
  DEE1 (9D02), прокрутка E10E..E149.
- **Прерывание**: на Векторе только кадровое, всегда RST 38h (IM 2 нет). В `start` (DE7B..DE81) `ld a,9Ch / ld i,a / im 2`
  → `im 1` + `nop`; заполнение таблицы 9C00 (DE83..DE8D) — убрать или оставить на перенесённом адресе (вреда нет).
  Вход 0x0038 = `jp vec_isr`; `isr` игры (BD2D) заканчивается `ei / ret` — подходит как есть. Частота та же, 50 Гц.
- **ПЗУ ZX не с нуля**, а с 0x1000 (0x0038 занят входом прерывания). Правки того же размера:
  `rnd` B5AB `and 03h` → `and 13h` и начальное `v_rnd_ptr` (B5BA) 0000 → 1000; пульт D29B `ld d,04h` → `ld d,14h`.
  Последовательность случайных чисел не меняется (те же байты ПЗУ).
- 55 указателей таблицы t_deckgfx (на графику 9670..9BC2) — каждый −0x6000.
- Ложные срабатывания не трогать: D407 `ld hl,8000h` (пауза), `ld b,8Eh..91h` (номера строк).
- Опция исправления DETECTOR: D498 `ld hl,t_detect_old` → `ld hl,2078h` (по умолчанию выключена, как в оригинале).
- Кэш зеркальных плиток (B4F1) пишет в таблицы указатели на копии — база кэша уже перенесена, правок не нужно.
- **Проверка до Вектора**: тот же скрипт с другим смещением можно собрать под ZX (окно в свободную память ZX нельзя —
  её нет), поэтому сверка переноса — на Векторе, гейт 1.6.

### 1.3. Старт
- Формат для стенда — `.r0m` 64 КБ с PC = 0 (как Knight Lore, Emu80 с `vector.z80`); для MiSTer — загрузчик
  со сжатием (как в портах `rom/*.rom`), распаковка по адресам раскладки.
- Код старта: `di`, порты Вектора (`out (0),88h`, бордюр, скролл FF), палитра в VBlank, копия ПЗУ ZX на 0x1000,
  `jp vec_isr` на 0x0038, SP = 0x61A5, `jp start` (DE70).
- **Стенды Z80 есть** (24.10.2026): ядро MiSTer с Z80 (как `Spirits-Z80.mgl`: `_Computer/Vector-06C`, образ в
  `games/VECTOR06`) и Z80-режим vector06js (`Z80_v06.js` + `z80_adapter.js`, страница `kvalley_z80.html?i:<файл>.r0m`;
  для безголового стенда `demo/run_vec.js` — подключить те же два файла).
- Прерывание на всех стендах одно — кадровое RST 38h (vector06js: `di` + `execute(0xff)`), поэтому игра переводится
  на вход 0x0038 (см. 1.2); правок эмулятора не нужно.

### 1.4. Экран: теневой → Вектор
Две ступени.
1. **Просто и медленно**: перевод теневого экрана ZX 4000–57FF в плоскость Вектора (столбцы, Y снизу вверх, поле ZX 256×192
   по строкам 32..223 плоскости). Вызывается в конце игрового кадра (крюк в `spr_pace` DD79) и после экранов-заставок
   (`scr_gameover`, пульт, лифт, захват). Цель — увидеть игру и проверить логику, не скорость.
2. **Быстро**: горячие пути пишут сразу в плоскость Вектора, теневой экран остаётся для текста и атрибутов:
   - `scr_copy` C05A (поле целиком) — переписать на столбцы (как в демо);
   - `spr_flush` B424 (окна спрайтов) — переписать, самомодификацию ширины/шага заменить;
   - `print_at`/`print_cont` B1FB/B1FF — знак сразу в плоскость (8 байт столбцом);
   - `cls_bitmap`/`cls_attr`, `scr_down8` — по месту.
   Грязные области (окна, строки текста) отмечать, чтобы перевод теневого экрана не трогал лишнего.
- Атрибуты на первом шаге игнорируются (ч/б). Ориентир «что ZX прятал атрибутами» — рецепт KL §10: мусор,
  спрятанный INK = PAPER, на Векторе будет виден — проверить заставку, панель, захват.

### 1.5. Ввод
- Опрос матрицы Вектора в прерывании (кадровое, 50 Гц) в таблицу; `in a,(c)` игры с B = ряд ZX заменить вызовом
  склейки, которая собирает ряд ZX из матрицы (таблица ZX-ряд → клавиши Вектора, как `vec_kbmat` в Knight Lore).
  Места: `input_read` B61F, `pause_check` (P), `menu_controls` (1–4), `panel_key` E21D (W), `dbg_monitor` (F7FE).
- Kempston (порт 1F) → джойстик «П» Вектора (порты как в tankwars/alien8), меню «4» оставить как «джойстик».
- **Важно**: обработчик прерывания игры (`isr` BD2D) — звук. Опрос клавиатуры встроить в начало `isr` (через склейку),
  порт 3 трогать только в VBlank.

### 1.6. Звук (первый шаг — работает, не точен)
- `isr` эффекты: `out (FE)` бит 4 → бит динамика Вектора (порт 00/01, как в портах-аналогах) или канал ВИ53.
- `play_tune` и `bonus_count` — жёсткие циклы бипером с `di`: на 3 МГц высота и темп ниже. На первом шаге оставить
  бипером с поправкой констант (0x1530 итераций ноты и периоды), точную подстройку — на этапе 3.
- Бордюр (`out (FE)` биты 0–2) — порт 02 или убрать.

### 1.7. Сверка с ZX (гейты этапа 1)
- **Гейт 1.5 «оживление»**: заставка, меню, старт, палуба видна, игрок ходит, прокрутка у края.
- **Гейт 1.6 «логика»**: пошаговая сверка состояния игры (AF00–B0FF, t_objs, t_population, t_deckdroids, счёт) Вектор
  против ZX по кадрам при одинаковом вводе. Случайность: `rnd` берёт R — в обоих стендах подменить `ld a,r` одной
  детерминированной последовательностью (на ZX — точкой останова в B5B1, на Векторе — патчем).
  Сценарии те же, что в `tools/cov_more.sh` (лифт, пульт, захват, трофеи, гибель, город).
- **Гейт 1.7 «картинка»**: снимки плоскости Вектора против экрана ZX (перевод ZX→раскладка Вектора) на кадрах сценариев.
- **Гейт 1.8 «темп»**: кадров на игровой кадр по сценариям против ZX (главный цикл сам выравнивает темп ожиданием
  в `spr_pace` при < 6 объектах).
- Выпуск этапа: `.r0m`/`.rom` Z80, запуск на MiSTer (если ядро с Z80), README «требует Z80».

## Этап 2. Перевод на i8080 (ванильный Вектор)
Рецепт — `~/projects/knightlore-v06c/docs/PORT_RECIPE.md` §5, §7–8, §12; ядро переводчика из KV.

> **Сделано 25.10.2026 (перевод, без ускорения).** `port/build.sh --i8080 [--ru]` -> `build/port8080/quaz_8080[_ru].r0m`.
> Источник — готовый образ Z80 (все правки порта, склейка, русские тексты): `tools/port8080.py` декодирует код трассировкой
> от входов (`tools/z80dec.py`; косвенных переходов нет — код переносится целиком), переводит в подмножество i8080 и
> раскладывает по освободившимся местам (код игры и склейки, мёртвый код, свободные области); данные остаются на своих
> адресах, поэтому стенды и таблицы не меняются. Метка `zXXXX` — команда XXXX образа Z80, `pcmap.txt` — соответствие адресов.
> - Флаги: `djnz`, `neg`, сдвиги CB, `bit`, `sbc hl` дают на i8080 другие S/Z/C — точный (длинный) вариант ставится, только
>   если флаг дальше читается (анализ живости по всему коду, возвраты — по местам вызова; склейка — всё живо).
> - Руками (`port/i8080.asm`): `blit_tile` (самомодификация — коды операций и вход в цепочку сдвигов через `jp`),
>   `ldir`/`lddr`/`rld` с сохранением A и флагов, `ld a,r` -> xorshift16, обёртка прерывания `isr80` (ячейки `z_a`,
>   `z_t`, `z_hls` на стеке — прерывание приходит посреди переведённой команды), `sub 1 / daa` -> десятичное вычитание.
> - Склейка: IX (опрос клавиатуры) — ячейка `z_ix`; `ld (nn),sp` — без стека (SP смотрит в буфер поля в `vec_scr_copy`);
>   на участках с SP на данных переводы со стеком запрещены (проверка сборщика); `attr_hl` больше не смотрит на адрес
>   возврата — места `ld (hl),c` и `ld (hl),47h` идут через `push af / ld a,… / rst 18h / pop af`.
> - Гейты: `tools/xcheck80.js` — покомандная сверка с образом Z80 (регистры и память на каждой метке, 100 млн команд);
>   `I80=1 [RU=1] tools/lockstep_all.sh` — сверка с ZX 12 сценариев × 4000 проходов (логика, картинка, цвет, чужие записи) —
>   зелёные; `I80=1 tools/lockstep_soak.sh`.
> - Темп (стенд, кадров на проход main_loop): без прокрутки ZX 5,03 / Z80 6,06 / i8080 9,05; с прокруткой 10,11 / 11,38 / 20,03.
>   Место: свободно 1229 байт (русская — 818). Дальше — ускорение горячих мест.
> - **Ускорение (25.10.2026)**, `tools/tempo.sh` (6 сценариев, кадров ТВ; ZX / i8080 было / стало): мини-игра 4,06 / 10,60 / 6,76,
>   ход 4,88 / 8,87 / 6,46, прокрутка 9,29 / 18,04 / 13,66. Сделано:
>   - управление в прерывании: матрица и ряды ZX считаются в `kbd_scan_80` при смене матрицы, `rst 10h` только выбирает;
>   - паузы по времени ZX (`spr_pace`, пауза, выбор стороны и тоны захвата, лифт, нота мелодии — звук уже на ВИ53, цикл только
>     держит время; на i8080 пустая итерация 20 тактов против 13,7 у ZX — паузы были в 1,46 раза длиннее);
>   - вывод через стек: `ldir`/`lddr` блоками по 64 (pop/push при di), `vec_spr_flush` (pop из полосы, змейкой),
>     `bg_restore` (push в полосу снизу вверх, прерывание при ei пишет в ещё не записанные строки); короткие копии с известным
>     BC — развёрнуто;
>   - `blit_tile`: сдвиг `rlca` + маски, счётчик в регистре, самомодификация только при смене сдвига/режима, быстрый отсев
>     столбцов вне полосы; `print_cont` и знак в плоскость; класс цвета — только при смене атрибута и для клеток по точкам;
>     `pal_set` (половина таблицы, `zxcol` по таблице); `xf_rowaddr`; `isr` игры без exx/ex af;
>   - переводчик: живость A (без сохранения в `z_a`), добавки в две дыры (`port/i8080.asm`, `port/i8080_fast.asm`);
>     копия ПЗУ 1000–13FF освобождена (`rnd` берёт байты из своего кода C000–C3FF). Свободно 1551 байт (русская — 1134).
>   Остаток: ожидание `spr_pace` (по времени ZX, ~24% хода), `blit_tile` (~30%), полная копия поля и классы при прокрутке.
> - **Ускорение, шаг 2 (25.10.2026)**: мини-игра 6,78 → 6,03, ход 6,45 → 5,62, прокрутка 13,69 → 13,11 (ZX 4,06 / 4,88 / 9,29).
>   - темп хода: вместо задержки `spr_pace` — `pace80` (`port/i8080_fast2.asm`): ждать (6 − n) × 0,492 кадра − W × (1 − 1/R)

### 2.1. Что переписывается руками (по аудиту)
- `isr` (exx, ex af,af'), `blit_tile` (exx/ex af,af' + самомодификация `jr` и операций), `scr_copy` (exx).
- `rnd`: `ld a,r` → свой генератор (16-битный сдвиговый, ~20 байт кода); копия ПЗУ ZX 0000–03FF для `rnd` больше не нужна
  (−1 КБ). Для CIRCUIT в пульте оставить только 0400–052B (300 байт) или нарисовать свои узоры. Сверка с ZX не страдает:
  в стенде ZX результат `rnd` всё равно подменяется последовательностью Вектора.
- `xf_timer` CE81: `daa` после `sub` → десятичное вычитание вручную.
- `score_show`: `rld` (3 места) → сдвиги тетрад.
- Блочные команды (`ldir`/`lddr`/`djnz`/`sbc hl`/`neg`/CB-сдвиги и биты) — переводчик.
- Самомодификация логики нет — только вывод (уже переписан на этапе 1.4).

### 2.2. Скорость (главный риск)
- По демо: полная отрисовка палубы 19 кадров, шаг прокрутки ≈ 1,7 кадра на сдвиг поля, вертикаль медленнее.
- Горячие места по профилю ZX: `blit_tile`, `deck_draw` (полосы при прокрутке), `scr_copy`, `spr_flush`, `bg_restore`.
  Решения из демо: полоса заранее (BAND), таблицы сдвигов, стековый вывод в di-блоках (рецепт KL §12).
- **Гейты**: пошаговая сверка i8080 против Z80-версии (этап 1 — эталон на той же раскладке), картинка, темп.
