# Порт на Вектор-06Ц с Z80 (первый порт, решение 24.10.2026)

> **Уточнено 24.10.2026 (PLAN.md, этап 1.1)**: окно 8000–9FFF переносится в **2000–3FFF (−0x6000)**, а 4000–5AFF
> остаётся теневым экраном ZX (27 прямых записей атрибутов не трогаем). I = 3Ch. Ниже везде, где написано −0x4000 / 4000–5FFF,
> читать −0x6000 / 2000–3FFF. **IM 2 на Векторе нет** — только кадровое RST 38h: `im 2` → `im 1`, 0x0038 = `jp vec_isr`,
> копия ПЗУ ZX — с 0x1000 (`rnd`: `and 13h`, v_rnd_ptr = 1000; пульт: `ld d,14h`). Подробно — PLAN.md 1.1–1.2.

Код игры исполняется как есть (Z80): `ld a,r`, `daa`, `exx`, IX/IY, самомодификация — не проблема.
Работа — только в «склейке» с железом Вектора и в раскладке памяти. Источник — `build/quaz.asm`
(собирается обратно байт в байт), правки — как замены в исходнике, проверка — пошагово с ZX.

## Память
Экран Вектора — 0x8000–0xFFFF (4 плоскости по 8 КБ), игра — 0x61A9–0xEE90. Видимой делаем **одну плоскость
0x8000–0x9FFF** (палитра: бит 3 индекса). Её содержимое у игры — только данные; переносим окно
**0x8000–0x9FFF → 0x4000–0x5FFF** (у ZX там экран, на Векторе свободно) с постоянным смещением −0x4000.
0x0000–0x3FFF (16 КБ) свободно под склейку и таблицы Вектора, но **0x0000–0x04FF занимает копия ПЗУ ZX**:
игра читает байты ПЗУ по абсолютным адресам — `rnd` (0x0000–0x03FF, по кругу) и картинка CIRCUIT на карточке части в пульте (0x0400–0x04FF).
Прерывания у игры через IM 2 (вектор из таблицы), адрес 0x0038 не нужен — склейка с 0x0500.
**Стек**: `ld sp` в игре нет — она живёт на стеке загрузчика BASIC (под RAMTOP 25000 = 0x61A8). На Векторе
задать SP = 0x61A5 (так при настоящей загрузке с ленты, `zx-stand/tapeload.lua`; игре хватает ~20 байт стека, минимум 0x6192) перед `jp start`.
60EE–60F5 (t_detect_old, читает лифт при DETECTOR) — нули, как в оригинале. Это устаревший адрес таблицы t_deckdroids (8078);
исправление — `ld hl,4078h` в D498 (после переноса окна): детектор начнёт подсвечивать палубы с дроидами. Решить при выпуске (опция).

Что ссылается на окно (всё найдено аудитом, `tools/audit.py` + разбор):
| где | что |
|---|---|
| `deck_draw` BE38, BE42 | `ld hl,9603h` (t_deckgfx), `ld hl,8080h` (буфер-полоса) |
| `scr_copy` C05A, C07D, C0A0 | источник 8300/8B00/9300 (переписывается целиком) |
| `strip_put` C1B7, C241 | t_field 8300 |
| D971, DF6C, E3DA | t_deckdroids 8078 |
| `start` DE7D | `ld a,9Ch / ld i,a` — страница таблицы IM 2 |
| `start` DE83, DE8B | таблица IM 2 9C00/9C01 |
| `start` DEE1 | начало кэша плиток 9D02 (v_cache_free) |
| прокрутка E10E..E149 | сдвиги t_field 8300..95FF |
| t_deckgfx 9603 | 55 указателей на графику 9670..9BC2 (переносятся вместе с окном +смещение) |
| кэш плиток (runtime) | B4F1 переписывает указатели таблиц на копии в кэше — база кэша уже перенесена |

Не адреса (ложные срабатывания): `ld hl,8000h` в D407 — счётчик паузы; `ld b,8Eh..91h` в xfer_game —
номера строк; `ld a,80h/99h/...` — флаги и коды. Регистр I и IM 2 на Векторе работают: шина при прерывании
отдаёт 0xFF, вектор берётся из 9CFF/9D00 (оба 0xE6) -> E6E6 -> `jp isr`.

## Экран и атрибуты ZX -> Вектор
Все записи в экран ZX идут через конечный набор процедур; координаты передаются экранными адресами ZX,
поэтому переписываются только процедуры (адрес ZX -> адрес Вектора внутри), места вызова не трогаем.
| процедура | что делает | на Векторе |
|---|---|---|
| `print_at`/`print_cont` B1FB/B1FF (+`print_comp`, `print_list`, `xf_glyph`) | знак 8 байт по адресу ZX | знак в столбец плоскости |
| `scr_down8` B070 | адрес ZX на знакоряд ниже | то же в раскладке Вектора (или оставить ZX-адреса и переводить при записи) |
| `cls_bitmap` B2C9, `cls_attr` B2E7 | заливки | заливка плоскости / палитра |
| `attr_rects` B5BC, прямые атрибуты (панель 5AA2/5AAE/5AB1, лифт, меню 58A3, захват) | цвет | палитра / игнор на первом шаге |
| `scr_copy` C05A | буфер поля -> экран | как в демо (полоса -> столбцы) |
| `spr_flush` B424 | окно спрайта -> экран | столбцы Вектора |
| `blit_tile` B07D, `strip_put` C1A5 | вывод в буферы | как в демо (раскладка буфера-полосы Вектора) |
| `dbg_monitor` B2F4 | отладочный монитор авторов (выключен; уходит в `jp F70F`, которого нет) | не трогать: v_mon_on = 0, вызов из input_read остаётся (опрос F7FE) |
Константы адресов экрана ZX в коде по функциям — см. раздел аудита; таблицы надписей (`print_list`) и
прямоугольников (`attr_rects`) содержат адреса ZX — читаются теми же процедурами.

## Порты и звук
- Клавиатура ZX: `in a,(c)` с B = ряд (input_read B61F, pause_check — P (DFFE), menu_controls — 1..4, dbg_monitor — F7FE, panel_key E21D — W (FBFE)).
  На Векторе — опрос матрицы в прерывании и таблица ряд ZX -> ряды Вектора (как в Knight Lore).
- Kempston (порт 1F) — заменить джойстиком «П» Вектора.
- Бипер ZX (`out (FE)`, бит 4) — `isr` (эффекты), `play_tune`, `bonus_count`, захват. На Векторе — ВИ53 или бит динамика.
- Бордюр (`out (FE)`, биты 0–2) — порт 02h Вектора или игнор.
- `isr` работает в альтернативном наборе (`exx`) и не сохраняет BC'/DE'/HL' — основной код их не использует
  (только AF', который `isr` сохраняет). Эффект: 8 байт (период, шаг, кадров, отрезков, режим, база, длина, следующий);
  на кадр — 255 полупериодов тона. Шум (0x11) — бипер по `rnd`.
- `play_tune` — два голоса бипером на жёстких циклах (нота 0x1530 итераций), прерывания запрещены.
  На Z80 Вектора (3 МГц, такты кратны 4) высота и темп сместятся — подстроить константы или перенести на ВИ53.
- Ввод: таблицы клавиш режимов `t_keys_*` (AFCF..AFFF) — записи [FE, ряд, маска]; Kempston — маски порта 1F.

## Скорость
Z80 Вектора — 3 МГц против 3,5 МГц ZX (и такты Вектора кратны 4). Главный цикл игры сам ограничивает темп
(цикл ожидания DD8D по числу объектов) — запас есть. Вывод палубы и прокрутка — по опыту демо.
