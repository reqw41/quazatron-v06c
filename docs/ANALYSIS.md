# Разбор оригинала ZX и демо прокрутки (24.10.2026)

## Инструменты разметки
- `zx-stand/run.sh` + `run.lua` — MAME `spectrum -exp kempjoy`. Меню: «4» (Kempston), ENTER, огонь.
  Движение — `QZ_MOVES="кадр:Right+Up,..."`. Есть трасса с тактами (`QZ_TRACE=T0-T1` → `prof.tr`),
  тап записей в экран (`QZ_TAP=1`) и снимки ОЗУ (`QZ_DUMP=кадр`).
- `tools/trace_prof.py` — такты по процедурам и горячим участкам; `tools/trace_calls.py` — дерево вызовов (грубое).
- `tools/mk_disasm.py` — дизассемблер по покрытию трассы: исполненное = код (`build/quaz.asm`).
- **Ghidra 12.1.4 (консольный режим, процессор Z80)** — `tools/ghidra/QuazExport.java`: засев кода по покрытию,
  функции по целям `call`, выгрузка функций (тела, вызывающие) и перекрёстных ссылок в `build/ghidra_*.txt`.
  Запуск: `analyzeHeadless build/ghidra_proj quaz -import
  orig/zx/quazatron_ram.bin -loader BinaryLoader -loader-baseAddr 0x4000 -processor z80:LE:16:default
  -scriptPath tools/ghidra -postScript QuazExport.java build/cov_pcs.txt build/call_targets.txt build`.
  REA (MCP) Z80 не открывает: в сырых образах у него только 6502/x86/ARM/m68k.

## Устройство вывода оригинала
- **Прокрутки как непрерывной нет.** Пока игрок ходит, поле стоит, перерисовываются только спрайты
  (около 320 байт за игровой кадр, 12,5 кадра/с). У края экрана (позиция игрока AF94/AF95) запускается сдвиг
  на 7 шагов по 16 точек (горизонталь) или 8 шагов по 8 строк (вертикаль). На каждом шаге:
  сдвиг буфера `ldir`/`lddr` (E10E–E15A), камера AF1C/AF1D += AF34/AF35, дорисовка открывшейся полосы (BE38),
  копия буфера в экран (C05A), около 8 кадров на шаг вместе с дроидами.
- **Буфер поля** 0x8300: 32 байта × 152 строки, линейный. C05A копирует его в экран ZX и ставит атрибуты
  по таблице B024 (полосы цвета по столбцам).
- **Таблица режимов** AF36, по 10 байт: +0 полная отрисовка, +0x0A влево (содержимое влево), +0x14 вправо,
  +0x1E вверх, +0x28 вниз. Блок копируется в AF2C: шагов, ширина (0x20 — все полосы, 1 — одна в 2 байта),
  ?, высота, первый байтовый столбец, первая строка, смещение карты (AF32/AF33), шаг камеры (AF34/AF35).
  Код направления — в AF2B.
- **BE38 — отрисовка палубы** вертикальными полосами по 4 байта (32 точки): полоса заливается 0xFF (C044),
  обходится карта по диагонали (AF6C/AF6D), плитки выводятся через BE08 → B4F1 (поиск графики) → B07D,
  полоса копируется в буфер (C1A5). Поддерево: B07D, B4F1, BE08, BE38, BFFF, C044, C12B, C19A, C1A5 (≈1,4 КБ).
- **Карта палубы** — 16×16 байт по указателю AFB4 (палуба 1: 0x63C5). Индекс клетки = `(d & 0x3C) << 2 | e >> 2`
  (в оригинале — перестановка бит через `rl/rr e`, BEF1). Клетка: биты 0–2 — тип, 3–6 — высота.
- **Графика плиток**: таблица указателей по 2 байта с 0x9603 (AFC2; для дроидов — 0xA403), номер плитки с 1.
  Перед данными байт-заголовок (младшая тетрада — число столбцов − 1, бит 0x20 — кадры анимации).
  B4F1 кэширует подготовленную графику в 0x9C00–0xA3FF (список A180, указатель B009).
- **B07D** — вывод плитки по столбцам 8 точек: [число столбцов] { dx, dy, флаги|высота, байты }.
  Режимы: б7 — стирание (`cpl; and (hl)`), б6 — запись, иначе `or (hl)`; режим и сдвиг 0–7 патчатся прямо в код
  (смещение `jr` в цепочку `add hl,hl`). Отсечение по строкам AF16/AF17.
- Дроиды (D5BB → DC24): собраны из частей, номер на корпусе — шрифтом из таблицы 61B0, буфер 0xE700.
  После них цикл ожидания DD8D, зависящий от числа объектов.
- Память: игра занимает 0x61A9–0xEE90 (≈36 КБ). Свободно 0x4000–0x61A8 (экран и переменные ZX)
  и 0xEE91–0xFFFF; 0x8600–0x95FF — это часть буфера поля, не свободно.

## Демо прокрутки (`demo/`)
- Отрисовка палубы — **переведённый код оригинала** (`demo/extract.py`: срез z80dasm по телам функций из Ghidra
  → ядро переводчика King's Valley). Вручную на i8080 написаны: B07D (`blit.asm`, сдвиг таблицами 3,5 КБ
  с 0x4000), C1A5 (полоса → столбцы экрана Вектора), C044 (заливка через `push`), сдвиги поля (`vecout.asm`,
  копирование через стек), адрес клетки карты (замена в `extract.py`).
- Данные — снимок ОЗУ идущей игры `orig/zx/state_play1100.bin` (0x61A9–0xDFFF на своих адресах).
  Видимая плоскость 0xE000 (бит 0 индекса палитры), поле 32 × 152 со строки памяти 0xE7.
- Проверки (стенд `demo/run_vec.js` на vector06js):
  * полная отрисовка совпадает с буфером 0x8300 оригинала **байт в байт** (`QZ_CMP=orig/zx/state_play1100.bin`);
  * после каждой прокрутки поле совпадает с полной перерисовкой при той же камере (`QZ_VERIFY=1`): 28 из 28.
- Скорость (Вектор 3 МГц, только палуба, без дроидов; замер по тактам процессора, `QZ_LOG=1`):

  | | первая версия (счётчик кадров, тогда без di — верен) | стало |
  |---|---|---|
  | полная отрисовка | 28,9 кадра | 19 кадров |
  | горизонтальная прокрутка, 7 шагов по 16 точек | 42 | около 25 (3,6 на шаг) |
  | вертикальная прокрутка, 8 шагов по 8 строк | 76 | около 33 (4,1 на шаг) |

  Счётчик кадров в ISR врёт (сдвиги и вывод идут при `di`, прерывания теряются), поэтому стенд меряет такты.
- Что дало ускорение:
  * буфер-полоса раскладкой Вектора (4 страницы `STRIP` = 0x5800, байт k строки r — (0x58+k)·256 + r) вместо
    4 байт на строку: в выводе плиток следующая строка — `inc l`, полоса в экран — `push` по 24 такта на байт;
  * вертикальная прокрутка: одна полоса в 64 строки при конечной камере в буфер `BAND` (0x5000), шаги только
    сдвигают поле и докладывают 8 строк. Параметры полосы: 8 строк поля = шаг карты (−2, +2), поэтому полоса
    со строки R0 получает смещение карты (03 − R0/4, FF + R0/4); нижняя граница AF2E = высота + 24.
    Одна полоса в 64 строки — около 18 кадров, в 8 строк — около 7: обход карты почти не зависит от высоты;
  * адрес клетки карты формулой, заливка полосы и сдвиги — через стек.
- Предел без аппаратной прокрутки — сдвиг поля: 4560 байт на шаг по 22 такта (`pop` + запись через HL),
  около 1,7 кадра на шаг в любую сторону. Остальное — отрисовка: около 1,5 кадра на горизонтальный шаг,
  около 15 кадров на вертикальную полосу (заминка в начале вертикальной прокрутки).
